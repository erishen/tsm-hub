# 数据处理协议（DPA）模板

**版本**：v1.0
**最后更新**：2026-09-11
**适用**：tsm-hub 自托管部署场景

---

## 重要说明

本文档是**数据处理协议（Data Processing Agreement, DPA）的模板**，供使用 tsm-hub 作为数据处理者的场景参考。由于 tsm-hub 是**自托管**软件，数据控制者（您）完全控制所有数据，tsm-hub 开发者不接触、不处理、不存储您的任何数据。

如您将 tsm-hub 作为服务提供给您的客户（即您是数据处理者，您的客户是数据控制者），可使用本模板作为双方签署 DPA 的基础。请根据实际情况修改，并咨询专业律师。

---

---

## 第一条 定义

1.1 本 DPA 中使用的术语与主协议和适用法律中的定义一致。

1.2 「个人数据」指与已识别或可识别的自然人（「数据主体」）有关的任何信息。

1.3 「处理」指对个人数据进行的任何操作或一系列操作，如收集、记录、组织、存储、改编、检索、使用、披露、传播、删除或销毁。

1.4 「服务」指数据处理者基于 tsm-hub 平台向数据控制者提供的 LLM 网关和能力池服务。

---

## 第二条 处理的主题、期限、性质和目的

2.1 **处理主题**：数据控制者在使用服务过程中提交给数据处理者的个人数据，包括但不限于：
   - API 请求中的消息内容（messages、prompt、content）
   - 用户标识符（如 Token Key 前缀、用户 ID）
   - 元数据（时间戳、IP 地址、User-Agent、模型名称、token 用量）

2.2 **处理期限**：自本 DPA 生效之日起，至主协议终止或数据控制者要求删除数据之日止（以较早者为准）。

2.3 **处理性质**：云服务/API 服务中的数据存储、传输和处理。

2.4 **处理目的**：
   - 提供、维护和改进服务
   - 对 LLM 请求进行路由、认证、限流和故障转移
   - 统计用量和生成账单
   - 安全监控和故障排查
   - 遵守适用法律的要求

2.5 数据处理者不得为上述目的以外的任何目的处理个人数据。

---

## 第三条 个人数据类型和数据主体类别

3.1 **个人数据类型**：
   - 标识符：Token Key 前缀、用户 ID（如有）
   - 通信内容：API 请求中的消息文本
   - 元数据：时间戳、IP 地址、User-Agent、模型名称、token 用量、状态码
   - 技术数据：设备信息、浏览器类型（如通过管理界面访问）

3.2 **数据主体类别**：
   - 数据控制者的最终用户（通过 API 调用服务的自然人）
   - 数据控制者的管理员和开发人员（使用管理界面的人员）

3.3 双方确认，本 DPA 不涉及特殊类别个人数据（如健康数据、生物识别数据等），除非数据控制者明确书面同意。

---

## 第四条 数据控制者的义务

4.1 数据控制者保证其向数据处理者提供的个人数据的收集和处理具有合法依据，并已获得数据主体的必要同意（如适用）。

4.2 数据控制者保证其提交给服务的内容不违反适用法律，不侵犯任何第三方的合法权益。

4.3 数据控制者应及时响应数据主体行使权利的请求，并在需要数据处理者协助时，以书面形式通知数据处理者。

4.4 数据控制者应遵守适用的数据保护法律，包括但不限于 GDPR、PIPL。

---

## 第五条 数据处理者的义务

5.1 数据处理者应仅根据数据控制者的书面指示处理个人数据，包括与数据传输相关的指示，除非适用法律要求否则处理。在此情况下，数据处理者应在处理前告知数据控制者该法律要求，除非该法律禁止此类告知。

5.2 数据处理者应确保有权处理个人数据的人员承担保密义务。

5.3 数据处理者应采取第八条规定的适当技术和组织安全措施。

5.4 数据处理者应确保分包处理者（如有）遵守与本 DPA 相同的数据保护义务。

5.5 数据处理者应在知道个人数据泄露后，不迟于 **72 小时**内通知数据控制者。

5.6 数据处理者应配合数据控制者进行数据保护影响评估（DPIA）和监管机构的审计。

5.7 数据处理者应在主协议终止后，根据数据控制者的选择删除或返还所有个人数据，除非适用法律要求存储。

---

## 第六条 数据主体权利

6.1 数据处理者应在收到数据控制者的请求后，在合理时间内（不超过 **30 天**）协助数据控制者响应数据主体行使以下权利的请求：
   - 访问权
   - 更正权
   - 删除权（被遗忘权）
   - 限制处理权
   - 数据可携带权
   - 反对权

6.2 数据处理者应提供管理界面和 API，使数据控制者能够自行执行上述操作（如删除特定 Key 的数据、清空用量记录等）。

---

## 第七条 数据泄露通知

7.1 数据处理者应在知道个人数据泄露后，不迟于 **72 小时**内以书面形式通知数据控制者，通知应至少包含：
   - 泄露的性质和可能的后果
   - 受影响的数据主体数量和个人数据类型
   - 已采取或拟采取的补救措施
   - 数据处理者的联系人信息

7.2 如无法在 72 小时内提供全部信息，可分阶段提供，但应说明延迟原因。

---

## 第八条 技术和组织安全措施

数据处理者应采取至少包括以下内容的技术和组织安全措施：

### 8.1 访问控制
- 管理接口需要 Admin Token 或 Session 认证
- API 访问需要有效的 Token Key
- 按 Key 隔离模型权限和配额
- 按 Key 隔离会话记忆命名空间

### 8.2 传输安全
- 支持 TLS/HTTPS（可配置启用，或通过反向代理提供）
- 与上游 LLM 提供商的通信默认使用 HTTPS
- Token Key 仅存储 SHA-256 哈希，不存明文

### 8.3 存储安全
- 自托管部署，数据存储在数据控制者控制的服务器上
- 建议 `config.json` 文件权限设置为 `600`
- 支持使用环境变量引用 API Key，避免明文存储
- 管理台展示 API Key 时自动脱敏

### 8.4 数据最小化
- 用量日志只记录元数据，**不记录请求内容**（messages、prompt、content）
- 支持配置数据保留期限，自动清理过期数据
- 支持一键清空用量数据和记忆数据

### 8.5 代码执行安全
- `execute_code` 工具使用 Docker 沙箱：禁网络、只读根、丢弃 capabilities、禁提权、资源限制、超时自动销毁
- 文件读取工具限制在配置的根目录内，不可越界读取
- URL 抓取工具默认拒绝内网/环回地址（SSRF 防护）

### 8.6 审计与监控
- 所有管理操作自动记录审计日志（含操作者、IP、时间）
- 审计日志默认保留 90 天，可配置
- 支持 Prometheus 格式指标监控

## 第九条 分包处理者

9.1 数据处理者可以使用分包处理者提供服务的特定部分（如上游 LLM 提供商、云基础设施提供商）。

9.2 数据处理者应确保分包处理者承担与本 DPA 相同的数据保护义务。

9.3 数据处理者应对分包处理者的行为承担全部责任，如同其自身行为一样。

9.4 当前主要分包处理者类别（数据处理者应在附录中更新具体清单）：
   - 上游 LLM 提供商（由数据控制者自行配置）
   - 云基础设施提供商（如数据处理者使用云服务）
   - MCP Server 服务（由数据控制者自行配置）

---

## 第十条 数据跨境传输

10.1 如个人数据需要传输到欧洲经济区（EEA）以外的国家或地区，数据处理者应确保：
    - 接收方所在国家/地区具有充分性认定；或
    - 双方签署标准合同条款（SCCs）；或
    - 存在其他适用的合法传输机制。

10.2 数据处理者应在数据控制者要求时，提供数据跨境传输的相关信息。

---

## 第十一条 审计权

11.1 数据控制者有权（或委托独立第三方审计师）对数据处理者遵守本 DPA 的情况进行审计，每年不超过 **一次**，提前 **30 天**书面通知。

11.2 审计应在数据处理者的正常营业时间内进行，不得不合理地干扰数据处理者的正常运营。

11.3 数据处理者应配合审计，提供必要的信息和访问权限。

11.4 如审计发现违规，数据处理者应在合理时间内（不超过 **30 天**）采取纠正措施。

---

## 第十二条 协议终止与数据删除

12.1 主协议终止后，数据处理者应根据数据控制者的选择：
    - 返还所有个人数据给数据控制者；或
    - 删除所有个人数据。

12.2 数据处理者应在主协议终止后 **30 天**内完成上述操作，并向数据控制者提供书面确认。

12.3 如适用法律要求数据处理者继续存储某些数据，数据处理者应告知数据控制者，并仅在法律要求的范围内保留数据。

---

## 第十三条 责任与赔偿

13.1 任何一方违反本 DPA 给对方造成损失的，应承担相应的赔偿责任。

13.2 数据处理者对数据主体提出的索赔承担责任的范围，以主协议约定的责任限额为限，但因数据处理者故意或重大过失造成的损失除外。
