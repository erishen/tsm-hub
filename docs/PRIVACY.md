# 隐私政策

**最后更新**：2026-09-11
**适用版本**：tsm-hub v1.0.0+

## 概述

tsm-hub（Tools + Skills + MCPs 能力中心）是一个自托管的 LLM 网关和能力池平台。本隐私政策说明 tsm-hub 在运行过程中收集、存储、使用和保护哪些数据，以及数据主体享有的权利。

tsm-hub 设计为**自托管**软件，您（数据控制者）完全控制所有数据。本软件不会向任何第三方发送数据（除您配置的上游 LLM 提供商外）。

---

## 一、我们收集哪些数据

### 1.1 配置数据

| 数据类型 | 说明 | 存储位置 | 必要性 |
|----------|------|----------|--------|
| 上游 Provider 配置 | API Key、Base URL、模型列表、优先级、权重等 | `data/config.json` | 必要 |
| 路由规则 | 模型路由策略、目标 Provider、故障转移配置 | `data/config.json` | 必要 |
| Token Keys | 对外签发的访问密钥（仅存储 SHA-256 哈希）、名称、权限、配额 | `data/config.json` | 必要 |
| 全局设置 | 监听地址、超时、限流、定价、TLS、CORS 等 | `data/config.json` | 必要 |
| MCP Server 配置 | MCP server 启动命令、参数、环境变量、远程 URL | `data/config.json` | 可选 |

**安全说明**：
- Token Key **只存储 SHA-256 哈希**，不存明文；创建时仅展示一次明文，2 分钟内可补看
- 上游 Provider API Key **建议使用 `env:` 前缀引用环境变量**，避免明文写入配置文件
- `config.json` 建议设置文件权限为 `600`（仅所有者可读写）

### 1.2 用量与审计数据

| 数据类型 | 说明 | 存储位置 | 保留期限 |
|----------|------|----------|----------|
| 用量流水 | 时间、Key ID、模型、输入/输出 token 数、状态码、延迟、上游 Provider | `data/usage/`（按天 JSON 文件） | 默认永久，可配置 `usage_retention_days` 自动清理 |
| 审计日志 | 管理操作（创建/修改/删除 Provider、路由、Key、设置等）、操作者、客户端 IP、User-Agent | `data/audit.db`（SQLite） | 默认 90 天，可配置 `audit_retention_days` |
| 会话记忆 | `remember`/`recall` 工具存储的键值对，按 Key 隔离命名空间 | `data/memory.db`（SQLite） | 永久，可手动清空 |

**重要**：用量流水和审计日志**只记录元数据，不记录请求内容**（messages、prompt、content、响应文本等均不存储）。

### 1.3 运行时临时数据

| 数据类型 | 说明 | 存储位置 | 保留期限 |
|----------|------|----------|----------|
| 登录 Session | 管理台登录会话 token | 内存 | 12 小时，或登出/重启后失效 |
| Key 明文临时缓存 | 新创建的 Key 明文（用于 2 分钟补看窗口） | 内存 | 2 分钟后自动清除 |
| 请求上下文 | 当前处理中的请求数据（含请求体） | 内存 | 请求结束后立即释放 |
| MCP 进程 | stdio 模式 MCP server 的子进程 | 系统进程 | 网关运行期间常驻，断开自动重连 |
| Docker 沙箱 | `execute_code` 工具的临时容器 | Docker | 执行结束后自动销毁 |

### 1.4 上游 LLM 提供商

当您通过 tsm-hub 调用上游 LLM 提供商（如 OpenAI、DeepSeek、Anthropic 等）时，**请求内容会发送给这些第三方提供商**。这些第三方提供商有各自的隐私政策，tsm-hub 无法控制其数据处理方式。建议您查阅各提供商的隐私政策。

## 二、我们如何使用数据

### 2.1 核心功能

- **请求路由**：根据配置的路由规则，将请求转发到合适的上游 Provider
- **认证授权**：验证 Token Key，检查模型权限和配额
- **限流与配额**：按 Key 限制请求速率和 token 用量
- **故障转移**：当上游 Provider 不可用时，自动切换到备用 Provider
- **用量统计**：统计各 Key、各模型的 token 用量和成本
- **能力池执行**：在服务端执行内置工具、MCP 工具、Skills 等

### 2.2 安全与运维

- **审计日志**：记录所有管理操作，用于安全审计和问题排查
- **健康监控**：监控上游 Provider 的健康状态和延迟
- **错误诊断**：记录错误信息（不含请求内容），用于问题排查
- **性能指标**：通过 `/metrics` 端点暴露 Prometheus 格式指标

### 2.3 我们不会做的事

- ❌ 不会将您的数据发送给 tsm-hub 开发者或任何第三方（除您配置的上游 LLM 提供商外）
- ❌ 不会用于训练任何模型
- ❌ 不会存储请求/响应内容（messages、prompt、content 等）
- ❌ 不会收集个人身份信息（PII），除非您主动在配置中包含
- ❌ 不会进行用户画像或行为分析

## 三、数据存储与安全

### 3.1 存储安全

| 措施 | 说明 |
|------|------|
| 自托管 | 所有数据存储在您自己的服务器上，您完全控制 |
| Token Key 哈希 | 对外签发的 Key 只存储 SHA-256 哈希，不存明文 |
| 密钥脱敏 | 管理台展示 API Key 时自动脱敏（前4位****后4位） |
| 文件权限 | 建议 `config.json` 设置为 `600`，启动时会检查并警告 |
| 环境变量引用 | 支持 `env:VAR_NAME` 方式引用 API Key，避免明文存储 |

### 3.2 传输安全

- **推荐使用 HTTPS**：可在配置中启用 TLS（`settings.tls`），或使用反向代理（Nginx、Caddy）提供 HTTPS 终端
- **未启用 TLS 时**：API Key 和用户数据在网络上以明文传输，**仅限受信任的内网环境使用**
- **上游通信**：与上游 LLM 提供商的通信默认使用 HTTPS

### 3.3 访问控制

- **管理接口**：需要 Admin Token 或 Session 认证
- **代理接口**：需要有效的 Token Key（sk-tr- 开头）
- **Key 权限隔离**：每个 Token Key 可配置允许的模型列表和配额
- **会话记忆隔离**：`remember`/`recall` 按 Key ID 隔离命名空间

## 四、数据主体权利

根据 GDPR、个人信息保护法等法规，数据主体享有以下权利。由于 tsm-hub 是自托管软件，这些权利由您（数据控制者）通过管理界面或 API 行使：

| 权利 | 说明 | 实现方式 |
|------|------|----------|
| **访问权** | 了解我们持有哪些关于您的数据 | 管理台「用量」「审计日志」页面，或 API 查询 |
| **更正权** | 要求更正不准确的数据 | 管理台编辑配置，或 API 更新 |
| **删除权** | 要求删除个人数据 | 管理台「用量」「记忆」页面一键清空，或删除特定 Key |
| **可携带权** | 获取数据的机器可读副本 | `data/` 目录下的 JSON/SQLite 文件可直接导出 |
| **限制处理权** | 限制对数据的处理 | 禁用特定 Key、关闭 `remember` 工具等 |
| **反对权** | 反对基于合法利益的处理 | 自托管软件，您完全控制，可随时停止使用 |

## 五、数据保留与删除

### 5.1 保留策略

| 数据类型 | 默认保留期 | 可配置项 |
|----------|-----------|----------|
| 用量流水 | 永久 | `usage_retention_days`（天），>0 时启动时自动清理过期文件 |
| 审计日志 | 90 天 | `audit_retention_days`（天） |
| 会话记忆 | 永久 | 可在「记忆」页面手动清空 |
| 配置数据 | 永久 | 可手动删除 |
| 登录 Session | 12 小时 | 硬编码，登出或重启后失效 |
| Key 明文临时缓存 | 2 分钟 | 硬编码，自动清除 |

### 5.2 删除方式

- **清空用量数据**：管理台「用量」页面 → 「清空全部历史」按钮
- **清空记忆数据**：管理台「记忆」页面 → 「清空全部记忆」按钮
- **删除特定 Key**：管理台「Keys」页面 → 删除按钮（同时吊销该 Key 的访问权限）
- **删除 Provider**：管理台「Providers」页面 → 删除按钮
- **完全重置**：停止网关，删除 `data/` 目录，重启后重新初始化

## 六、Cookie 与本地存储

tsm-hub 管理界面使用浏览器的 `localStorage` 存储：

| 数据 | 说明 | 保留期 |
|------|------|--------|
| 登录 Session Token | 管理台登录凭证 | 12 小时，或手动登出 |
| 界面偏好 | 主题、折叠状态等（如有） | 永久，可手动清除 |

**不使用**：第三方 Cookie、跟踪 Cookie、广告 Cookie、分析脚本。

---

## 七、儿童隐私

tsm-hub 是面向开发者和企业的技术产品，不面向 13 岁以下儿童。我们不会故意收集儿童的个人信息。如果您认为我们可能收集了儿童的信息，请联系我们删除。

---

## 八、第三方服务

tsm-hub 本身不集成任何第三方分析、跟踪或广告服务。但当您配置上游 LLM 提供商时，请求内容会发送给这些第三方。以下是可能涉及的第三方类别：

- **LLM 提供商**：OpenAI、Anthropic、Google、DeepSeek、Moonshot 等（您自行配置）
- **MCP Server**：您自行配置的 MCP 工具服务
- **Docker Hub**：如使用 `execute_code` 沙箱，可能从 Docker Hub 拉取镜像

请查阅各第三方服务的隐私政策。

---

## 九、数据跨境传输

tsm-hub 是自托管软件，数据存储位置由您决定。如果您的服务器位于某一司法管辖区，而您配置的上游 LLM 提供商位于另一司法管辖区，则请求内容可能涉及跨境传输。请确保您的使用符合相关数据保护法规。
